# Find in PR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A find bar on Files changed that searches every file's paths, changed lines and shown context at once, counts the hits, and steps through them across files with the current one highlighted, taking over Cmd+F / Ctrl+F.

**Architecture:** The search is a pure function over data the browser already has (the review view's clusters) plus each file's hunks and expanded context, which a batcher prefetches through one new server route into the same React Query cache entries the diff reads. A module store holds the bar's open state and term (the app header's button and the page both read it); FilesPage computes the hits, the caret and the per-file views it hands to the tree, the file headers and the diff bodies; the diff paints hits as marks through `CodeLine` and scrolls to the current one the way a thread landing does. Expanded context moves from DiffBody's local state to a page-level store so it survives closing a file.

**Tech Stack:** Fastify + git CLI (server), React + TanStack Query + Tailwind (web), Vitest (unit; jsdom for components), Playwright with the fake gh (desktop and phone projects), Biome.

**Spec:** `docs/superpowers/specs/2026-11-05-find-in-pr-design.md`

## Global Constraints

- Principle 2: the search hides, filters, collapses, reorders and marks nothing reviewed; the tree keeps every file; the count never looks complete while hunks are on their way (spinner), and a file that couldn't be searched is reported (warn + Retry), never skipped silently.
- Principle 5: the bar fits 360px with no horizontal page scroll; every control (box, ↑, ↓, ✕, Aa, header button) is at least 40px tall.
- Principle 6: colors from `@theme` tokens only; `find-mark` is an opaque fill of the accent's hue (like `span-mark`), `find-current` an opaque fill of `--color-orange`; neither is a review-state color; both pass the contrast tests in `theme.test.ts`.
- Exact copy: placeholder and `aria-label` **"Find in PR"**; count **"3 of 41"** (phone: **"3/41"**), **"0 of 0"**; spinner label **"Searching files…"**; retry **"N files couldn't be searched · Retry"**; tooltips **"Previous (Shift+Enter)"**, **"Next (Enter)"**, **"Close (Esc)"**, **"Match case"**; tree chip `aria-label` **"N matches"**; help group **"Files changed"**.
- Keys: `Mod+f` opens (not while typing in a field); in the box `Enter` / `Shift+Enter` / `Escape`; outside the box while open `Mod+g` / `Shift+Mod+g`.
- Setting key `crb.find.matchCase`, off by default (`viewSetting`).
- Route `GET /api/r/:id/files/hunks?revision=<r>&indexes=1,2,3`, at most `HUNKS_BATCH` (25) per request, 400 on more or a malformed index, 409 `stale` on another revision; a file whose text can't be read answers with its own `error`.
- Typing never scrolls or opens a file; only a step does. The caret after typing is the first hit in the open file, else the first hit after it in reading order (wrapping), else the PR's first; it is unshown until the first step.
- Branch `search`, worktree `.worktrees/search`; each task on its own branch from `search`; commits via `git commit --only -- <paths>`; never push except the gallery repo in Task 11. `pnpm verify` before saying a task is done; `pnpm flake-check` on every new Playwright test (spinners and gates are involved).

## Review Focus

1. A term that matches across a line's folded-length change (`"İstanbul"`, term `"stanbul"`) → the mark starts at column 1 of the original string, never at the folded string's column (Task 2 unit).
2. The hunks of the open file arrive (or a batch lands) while the caret sits on a changed-line hit → "n of m" changes but the same characters stay current, and the count equals both sources' hits with none twice (Task 2 property test; Task 9 unit).
3. Refresh brings a new revision while the bar is open with a term → the prefetch restarts for the new revision; no 409 is surfaced as "couldn't be searched" (Task 9 unit: the old prefetcher is stopped, a new one queued).
4. A whitespace-only collapsed cluster (Ignore whitespace on) holds the current hit → the cluster opens and the row is shown, and switching to side by side keeps the same current hit (Task 6 unit; Task 10 e2e).
5. A term with hits only in a file whose batch failed → "0 of 0" is never shown as final: the warn icon says N files couldn't be searched, Retry fetches them and the count rises (Task 8 unit; Task 10 e2e with a routed 500).

// src/web/files/find/findInPr.ts
import type { DiffLine, DiffSide, FileHunks, FileView } from "../../../shared/types";

/** Where a hit is: a path, an old path, or a line on one side. */
export type HitSide = "path" | "oldPath" | DiffSide;

/** A hit's place: file index, side, line number (0 for a path), UTF-16 column. */
export interface HitPos {
	index: number;
	side: HitSide;
	line: number;
	col: number;
}

export interface Hit extends HitPos {
	/** Matched length in UTF-16 units (the term's, in the original string). */
	len: number;
}

/**
 * Every occurrence of `term` in `text`, non-overlapping, left to right;
 * case-insensitive unless `matchCase` (a case-insensitive regex over the
 * original string: columns are the original's, never a folded copy's).
 * None for an empty term.
 */
export function occurrences(text: string, term: string, matchCase: boolean): { col: number; len: number }[];

/** One searchable line of a file: its side, number and raw text. */
export interface SourceLine {
	side: DiffSide;
	line: number;
	text: string;
}

/**
 * A file's lines in the order the diff shows them. Without hunks: each
 * cluster's removed lines (LEFT, oldStart + i) then added lines (RIGHT,
 * newStart + i), clusters in file order (a "file" cluster has none).
 * With hunks: for each hunk, first the expanded `context` lines whose newNo
 * lies before it and after the previous hunk (sorted by newNo, first of a
 * duplicate newNo wins, one inside a hunk's new range ignored), then the
 * hunk's lines (del → LEFT:oldNo, add and context → RIGHT:newNo); then the
 * expanded lines after the last hunk.
 */
export function fileLines(file: FileView, hunks: FileHunks | undefined, context: readonly DiffLine[]): SourceLine[];

/**
 * The PR's hits in reading order: for each file (in the order given: the
 * tree's), its path's hits, then its old path's, then its lines' (fileLines)
 * in column order. Binary files and submodules have path hits only.
 */
export function findInPr(
	term: string,
	files: readonly FileView[],
	hunksOf: (file: FileView) => FileHunks | undefined,
	contextOf: (file: FileView) => readonly DiffLine[],
	matchCase: boolean,
): Hit[];

export const samePos = (a: HitPos, b: HitPos): boolean => …;
/** The hit's place in `hits`, -1 when it isn't one. */
export function hitIndex(hits: readonly Hit[], pos: HitPos): number;
/** Hits per file index (files with none are absent). */
export function countsByFile(hits: readonly Hit[]): ReadonlyMap<number, number>;

/** The current hit and whether a step has shown it (scrolled to it). */
export interface Caret {
	pos: HitPos;
	shown: boolean;
}

/**
 * The caret after the term changes: the first hit in file `openIndex`, else
 * the first hit in a file after it in `order` (file indexes in tree order),
 * wrapping, else the PR's first hit; unshown. Null without hits.
 */
export function caretAfterTyping(hits: readonly Hit[], order: readonly number[], openIndex: number | null): Caret | null;

/**
 * A step: an unshown caret becomes shown where it is; a shown one moves
 * to the next (`1`) or previous (`-1`) hit, wrapping at both ends. Null
 * without hits.
 */
export function stepCaret(hits: readonly Hit[], caret: Caret | null, dir: 1 | -1): Caret | null;
```

export const fetchHunksBatch = (revision: string, indexes: readonly number[]) =>
	request<HunksBatch>(`/api/files/hunks?${new URLSearchParams({ revision, indexes: indexes.join(",") })}`);
/** A revision's hunks and context never change; kept this long unobserved, so a search's prefetch outlives the bar. */
export const HUNKS_KEPT_MS = 60 * 60_000;
// hunksQuery and contextQuery gain `gcTime: HUNKS_KEPT_MS`.

// src/web/files/find/hunksPrefetch.ts
/** Batched requests out at once. */
export const HUNKS_IN_FLIGHT = 2;

export interface PrefetchSnapshot {
	/** Files asked for and not answered yet (queued or in flight). */
	pending: number;
	/** Files whose request failed or whose answer carried an error, by index, in the order they failed. */
	failed: readonly number[];
}

/**
 * Fetches files' hunks in batches of HUNKS_BATCH, HUNKS_IN_FLIGHT requests
 * at a time, in the order queued, and puts each answer in that file's own
 * hunksQuery cache entry (so the diff reads the same data). Skips a file
 * whose entry is already a success or fetching (a file just opened), or
 * already queued. `stop()` drops the queue; answers of requests out still
 * land in the cache.
 */
export class HunksPrefetcher {
	constructor(client: QueryClient, revision: string, fetchBatch: typeof fetchHunksBatch = fetchHunksBatch);
	queue(indexes: readonly number[]): void;
	/** Queues the failed files again (in their order) and clears `failed`. */
	retry(): void;
	stop(): void;
	subscribe(onChange: () => void): () => void;
	snapshot(): PrefetchSnapshot;
}

/**
 * The order the prefetch asks for files: the open file's position in
 * `files` (tree order) first, then outward alternating after and before it
 * (i+1, i-1, i+2, i-2, …); from the start when none is open. Files with no
 * lines (binary, submodule) are left out.
 */
export function prefetchOrder(files: readonly FileView[], openIndex: number | null): number[];
```
