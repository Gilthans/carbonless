# Re-review after new pushes: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the author pushes, the reviewer re-reads only the author's own changes, every mark and unresolved thread lands where it belongs or says why not, and any earlier patch set opens exactly as reviewed.

**Architecture:** Pure pieces in `src/shared/` (tracer, carry, thread placement) take diff hunks, rename pairs and states and return results; `src/server/rereview/` runs git (shape detection, the virtual rebase `merge-tree --write-tree B2 H1`, the interdiff `diff(H1', H2)`) and feeds them; the store gains `carried` and `thread-placed` events, per-patch-set folding and `-base` pin refs; the page gets the patch set graph, a toast, the since view, placed threads and the verdict's since line. Six PRs on Gilthans/carbonless, in order; each builds on the previous one's interfaces.

**Tech Stack:** TypeScript, Node 24, Fastify + git CLI, React + TanStack Query, Vitest (+ fast-check, new dev dependency), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-04-re-review-design.md` (scenario ids C1–C19, P1–P16, I1–I13, S1–S10, X1–X8 are tables in `docs/superpowers/specs/2026-11-02-re-review-scenarios-and-prior-art.md`). Read both before any task.

## Global constraints

- Design principles 1–8 in `CLAUDE.md`. Principle 2 is the one most at risk here: no carry, placement or UI path may make an unreviewed cluster look reviewed; a corrupt event leaves the cluster unreviewed.
- Principle 3: the storage change is measured (one `carried` event per rule, 200 clusters, asserted under 16 KiB raw) and documented in `docs/review-data-storage.md` in the same PR.
- Principle 7: every history-sensitive behaviour is proven on the methodology matrix, never on one fixture shape.
- Principle 8: every engine answer has a spinner in its slot until it arrives; the toast, the graph and the page never wait for the engine.
- The tracer, carry and placement modules import nothing from `src/server/` and never call git or do I/O. The tracer never searches by text across lines and never assumes the new commits descend from the old ones.
- Vocabulary in code: `revision` stays the snapshot id's name in types and routes (it already is everywhere); comments and docs call it the snapshot id. "patch set" is `patchset` in identifiers, as today.
- Keys: cluster keys are 64 hex characters (sha256), repeated keys carry a `:2` suffix (`src/server/diff/identity.ts`).
- Phone: every new control is 40px, the page never scrolls sideways (`expectNoPageOverflow` in `e2e/files-ui.ts`), and every Playwright spec runs in the phone project too.
- Copy: "viewing", "comparison base" ("comp. base" on a phone), "up to date", "3 new commits · f9e8d7c", "reworked", "new", "carried", "gone", "conflict", "changed since", "Not in this comparison", "file deleted", "Line rewritten since PS1", "See on PS1", "as reviewed · read-only".
- No commit attribution anywhere in this round: fates never name a commit; the trailing thread group says "file deleted" and the original path only.
- Keyboard: Ctrl+`[` / Ctrl+`]` move the viewing marker, Ctrl+Shift+`[` / Ctrl+Shift+`]` the comparison base; no key views the head on its own (Ctrl+`]` past the newest patch set does). `matchesKeys` in `src/web/shortcuts.tsx` already understands `Ctrl+` and `Shift+`.
- Commits: `git commit -m … --only -- <paths>`; never a bare `git stash`. Each PR: brief, fresh review, `pnpm verify` green, CI green. PRs 1–3 merge without the owner; PRs 4–6 wait for the owner's look at a branch instance and the gallery demo.
- Real-PR data (gytpol/active-directory-domain-agent#48) never enters the repo, tests, fixtures or commit messages.

## Review focus

Inputs the spec implies but no task's tests would otherwise exercise; each line's test is added to the owning task below.

1. **A `carried` event naming a `from` patch set that does not exist, or a `fromKey` that was `unreviewed` in it** (a forged or stale event): the fold ignores the entry and the cluster stays unreviewed. (Task 2.2.)
2. **A target cluster whose added lines trace exactly but whose removed lines were changed by the base, not the author** (P2/I13 neighbour): the removed lines differ byte for byte, so no carry; the cluster shows as reworked, never carried. (Task 3.3.)
3. **A thread anchored on a line number past the end of the file in its own snapshot** (GitHub data drift, C19): the tracer returns `unplaced("outside")`, never throws, never places. (Task 1.2.)
4. **The head moves twice while the page is open** (push, then force-push back, S6): the rail's last slot stays one width, the toast's count updates, and the connector card reflects the latest triple; a `GET /rereview` for a superseded head is discarded by key, not shown. (Task 4.2.)
5. **`merge-tree` prints a conflict for a file the PR deletes or renames**: the interdiff lists the file with `conflict: true` and its full new diff from `B2`, and the carry treats its clusters as new. (Task 3.2.)

### Task 1.2: Position trace

**Files:**
- Create: `src/shared/tracer/trace.ts`, `src/shared/tracer/index.ts`
- Test: `src/shared/tracer/trace.test.ts`

**Interfaces:**
- Consumes: Task 1.1.
- Produces:
  ```ts
  export const TRACER_VERSION = 1;
  export interface Position { side: DiffSide; line: number }          // DiffSide from src/shared/types.ts
  export interface TraceDiffs {
    ac: LineMapper;          // old base → new base, this file
    bd: LineMapper;          // old head → new head, this file (through its rename pair)
    cd: LineMapper;          // the new snapshot's own diff, this file
    oldLineText?: (pos: Position) => string | null;   // text in the old snapshot, for `changed`
    newLineCount?: { LEFT: number; RIGHT: number };   // file lengths in the new snapshot, for "outside"
  }
  export type Placement =
    | { kind: "placed"; side: DiffSide; line: number; became?: "context" }
    | { kind: "changed"; side: DiffSide; line: number; oldText: string | null }
    | { kind: "unplaced"; reason: "deleted" | "rewritten" | "base-changed" | "outside"; nearest: Position | null };
  export function tracePosition(pos: Position, diffs: TraceDiffs): Placement
  export function traceRange(start: Position, end: Position, diffs: TraceDiffs): { start: Placement; end: Placement; collapsed: boolean }
  export function traceSpan(span: { startCol: number; endCol: number }, oldLineText: string, newLineText: string): { startCol: number; endCol: number } | null
  ```
  Decision table (the GitLab one, from the scenarios doc's GitLab section): a `RIGHT` line L: `bd.oldToNew(L)` = N → `cd.newToOld(N) === null` ? `placed(RIGHT, N)` : `placed(RIGHT, N, became: "context")`; `bd.oldToNew(L) === null` → `h = bd.hunkRemovingOld(L)`; `h.newCount > 0` → `changed(RIGHT, h.newStart + min(L − h.oldStart, h.newCount − 1), oldText)`; else `unplaced("deleted", nearest = the last old line above L that maps)`. A `LEFT` line L: `ac.oldToNew(L)` = N → `cd.oldToNew(N) === null` ? `placed(LEFT, N)` : `placed(RIGHT, cd.oldToNew(N), became: "context")` (the PR no longer removes it); `ac.oldToNew(L) === null` → `unplaced("base-changed", nearest)`. A position whose landing lies outside the new file (`newLineCount` given for that side and the landing line exceeds it, or L < 1) → `unplaced("outside", null)`; the old file's length is not the test (a file that shrank still has valid landings). `traceRange`: both ends; if the traced end precedes the start, `collapsed: true` and both equal the end. `traceSpan`: the span's text (`oldLineText.slice(startCol, endCol)`) found once in `newLineText` → its columns; not found or found twice → `null`.

- [ ] **Step 1: Write the failing tests**, one `it` per scenario it owns, hunks hand-written: C1 (lines inserted above → placed on the new number), C2 (edited → changed with the old text), C3 (deleted → unplaced deleted, nearest above), C4 (range partly changed → start placed, end changed), C5 (LEFT line, base changed it → base-changed), C6 (context line, base changed it → changed), C13 (changed then reverted → placed), C15 (duplicate lines: positions pair by hunk, never by text: two identical lines, the second moved, the first stays), C16 (whitespace-only edit → changed; the caller decides the whitespace chip), C17 (`traceSpan` found / not found / ambiguous), and Review focus 3 (line past the end → outside). C7, C9–C12, C14, C18, C19 are covered elsewhere (renames and other heads are inputs: PR 3 and PR 5; C14 is C2; C18 has no position; C19 is the real-PR check) — say so in a comment at the top of the file. Then the property test: for random old/new texts built by random edit scripts (fast-check), with `bd` = the diff of the script and `cd` = a random diff, every `placed` lands on a line whose text equals the old text, every `changed` carries the old text, and no position is `placed` on different text.
- [ ] **Step 2: Run** `pnpm test src/shared/tracer/trace.test.ts` — FAIL.
- [ ] **Step 3: Implement** `trace.ts` per the table; `index.ts` re-exports both modules.

  ```ts
  export interface TargetFile { path: string; oldPath?: string; clusters: Cluster[]; bd: LineMapper /* source head → target head, by path pair */; ac: LineMapper /* source base → target base */ }

  ```
  Rule (spec, Carry): for each target file, for each source patch set latest first, for each source cluster of the file (or its `oldPath`) whose state is human `reviewed` or `crossed-off`: trace its added range through `bd` and its removed range through `ac`; every line must map and the images must be contiguous; the target cluster whose `newStart/newCount` equals the traced added range and whose `oldStart/oldCount` equals the traced removed range (a pure addition matches on the new range only, a pure deletion on the old range only) is the image; carry when `removed` and `added` are equal arrays byte for byte (`rule: "rename"` when the path pair differs, else `exact`); otherwise the image is `reworked`. The walk back stops at the first patch set with any human state for that cluster key (an `unreviewed` human entry blocks older patch sets). A source cluster with no image is `gone`. Context plays no part; `interdiffPaths` is advisory only (a carried cluster in an interdiff path is still carried: the interdiff can be non-empty elsewhere in the file). File-level clusters (`kind: "file"`) carry when the file's `newOid`-based key is identical, which the key already encodes: carry on equal `key` for them.
